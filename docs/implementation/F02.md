# F02 — durable workflow, crew and background recovery

Status: shipped and release verified on macOS/Linux; see [F14](F14.md).
This work package does not claim a live-provider reliability score.

## Implemented behavior

- Workflow run checkpoints use schema 2. They atomically persist completed step
  IDs, full dependency outputs, step results, loop iteration/feedback, held gates,
  in-flight/uncertain steps and a digest binding the workflow, loop, checkout and
  dry-run mode. A changed specification cannot silently reuse old completion.
- Checkpoint writes use a same-directory exclusive temporary file, fsync, atomic
  rename and (on POSIX) directory fsync. Mutations are locked. A failed
  serialization leaves the previous checkpoint intact. Active schedulers have a
  PID/host/token identity; stale scheduler writes cannot overwrite another owner.
- Parallel results are all folded and checkpointed even if an earlier sibling
  fails. Completed sibling effects are not forgotten and rerun during recovery.
  Held approval outputs are reused rather than executing the held step again.
  Loop reopening persists invalidation, feedback and iteration counters together.
- Interrupted workflow steps are explicitly marked as uncertain. Their resumed
  model input says the prior effects are UNKNOWN, provides partial output and
  saved dependencies, and asks the model to inspect/reconcile before choosing
  what remains. The scheduler does not replay prior commands or invent success.
- Crew claims carry a unique scheduler fencing token, PID, host and heartbeat.
  A second scheduler preserves a live claim even when its heartbeat is old.
  Persisted child PID ownership also protects a still-live child after its
  scheduler dies. Completion and retry updates are fenced. Full dependency
  outputs are retained instead of silently truncating them at 2,000 characters.
- When the crew scheduler and a known child are dead, remaining attempts are
  model-directed reconciliation attempts, with explicit unknown-outcome context
  and the previous worktree location. Already-completed tasks remain complete.
  Dynamic scheduling exits when another scheduler owns the remaining claims,
  rather than spinning. Normal scheduler exits release unfinished leases.
- Background tasks bind their immutable execution specification and persist a
  session UUID/configuration/transcript location before agent execution. The
  initial process receives `--session-id`; a recovered process receives
  `--resume` for that same saved session, not a fresh copy of the task prompt.
- Background list/restart reconciles dead workers. A surviving agent prevents a
  duplicate worker. A matching terminal saved result completes the task without
  another model run; completed model work awaiting publication is not repeated.
  Valid interrupted transcripts resume with completed tool results retained.
  Unpaired tool calls are explicitly disclosed (ID/name/input) as UNKNOWN
  OUTCOMES for model inspection/reconciliation. They are never synthesized as
  successful tool results.
- Steering uses stable message UUIDs, persisted acknowledgements and transcript
  deduplication. A completed inbox batch advances its durable offset only after
  acknowledgements, so a restart neither discards pending messages nor blindly
  reinjects already-persisted messages.
- Fixed a pre-existing completion bug: the 500 ms inbox polling loop repeatedly
  reset the 1 s stdin-close timer after a final result, keeping completed agents
  alive indefinitely. The timer is now scheduled once and only cleared by new
  steering.

## Deliberate boundaries and migration

This is not an exactly-once guarantee for arbitrary shell, network or external
service effects. A crash between an external effect and its tool-result journal
cannot prove the effect's outcome. The model receives that uncertainty and
chooses how to inspect/reconcile under the user's existing permissions. No new
mandatory isolation preset, model strategy or public command was introduced.

Malformed/torn/missing transcripts, mismatched session identities, changed
specifications and legacy workflow checkpoints without a digest/output journal
cannot authorize automatic resume. Workflow schema-1 state is preserved and
reports an explicit migration error; inspect prior work and use the existing
`ur workflow reset <name>` to begin a new run. Manual `workflow done` remains an
explicit operator attestation, with an empty output if none was recorded.

Local PID liveness is conservative: permission errors and PID reuse retain
ownership rather than authorize duplicate execution. A foreign-host owner is
not declared dead from a local probe. A scheduler killed between child launch
and durable child-PID persistence leaves an unidentifiable crew claim retained;
inspect actual processes/work and use the existing crew reset after
reconciliation. Interrupted publication is reported as ambiguous and is not
blindly repeated (inspect the branch/PR first). Recovery inspection currently
bounds a background transcript/output to 64 MiB and fails visibly above it.

No paid/live provider calls, remote-host failure tests, Windows release
qualification or external PR-publication crash experiment are included here.

## Files

- `src/services/agents/durableState.ts`: atomic writes, mutation locks and process
  ownership/liveness utilities.
- `workflows.ts`, `executor.ts`, `runWorkflow.ts`: complete durable DAG execution
  state, ownership, digest checks and reconciliation inputs.
- `crew.ts`, `cliStepRunner.ts`, `src/utils/execFileNoThrow.ts`: claim fencing,
  child process ownership, full dependency outputs and recovery prompting.
- `backgroundRunner.ts`: task reconciliation, pinned session continuation,
  stream/inbox durability, result identity and interrupted-publication handling.
- `test/durableRecovery.test.ts`: real process/file failure fixtures, isolated
  from live providers and without parent-process module mocks.

## Validation

Run from the shared workspace using pinned Bun 1.3.14:

```sh
bun test test/durableRecovery.test.ts test/agentPlatformPatterns.test.ts test/crewWorkerRecovery.test.ts test/backgroundCancellation.test.ts test/agenticCi.test.ts --timeout 120000
bun x tsc --noEmit --pretty false
```

The new fixtures kill real scheduler processes and headless fixture processes;
verify dependency output restoration and a single file effect; preserve a live
crew/agent despite dead parent or old heartbeat; reject stale completion tokens;
resume valid unknown-outcome work with explicit model reconciliation context;
refuse changed/corrupt state; retain completed parallel siblings; and verify
atomic-write failure and approval-hold recovery. These fixtures test production
orchestration and process arguments, not model judgment or provider quality.
