# F06/F07 — memory and repository retrieval

Status: locally verified (release verification remains with the release owner).

## Implemented

- One canonical `semantic-memory` and `code-index` command; existing aliases
  remain compatible. Persisted format upgrades happen in place.
- Shared Unicode/body lexical retrieval, optional validated local embeddings,
  explicit embedding availability/fallback, cancellation and bounded requests.
- Memory SHA-256 source provenance and real line ranges; query-time source
  revalidation; recursive source discovery; edited/deleted cache removal;
  explicit expiry, evidence anchors, supersession and conflicting-fact metadata.
- Automatic recall uses bodies, considers the whole store before supersession,
  preserves model-directed relevance selection, exposes competing facts, and
  rejects memories changed while selection was running. Optional configured
  embeddings are cached by source digest/model; lexical mode is observable.
- Code searches revalidate file hashes and exclude changed/missing sources.
  Path filters precede top-k selection. Ranking combines lexical relevance,
  embeddings (when available), symbol declarations and import neighbors.
- Default code, graph and repo builds no longer silently stop at 5,000 files.
  Coverage records explicit caps, oversized/unreadable files, chunk truncation.
- Graph/repo artifacts validate file hashes too. Repository artifacts from
  mismatched build generations are rejected; cached JSON is cloned before
  freshness filtering so one query cannot corrupt future query state.
- Atomic private cache snapshots, input-vector validation and interrupted-build
  preservation; current technical documentation and command/tool help updated.

## Guarantees and practical bounds

- Freshness is checked at source read time, not an atomic transaction against
  all concurrent filesystem writes. New sources appear after build/watch;
  stale indexed sources are omitted immediately by search.
- Natural-language contradiction resolution remains with the model. The
  retriever marks explicit conflict keys/duplicate IDs; it does not invent
  inferred facts or impose execution strategy.
- Metadata-free legacy memories remain usable. Absence of a provenance anchor
  is not claimed as proof that an associated historical test still passes.
- Auto recall uses embeddings only when UR_MEMORY_EMBED_MODEL is configured;
  explicit semantic-memory attempts the configured/default local model and
  reports fallback. No embedding model was installed on this machine, so live
  embedding-model quality remains an external measurement prerequisite.
- Source hashes provide provenance/freshness, not authenticity. Existing
  memory-integrity signing remains separate. Removing a cache is not forensic
  erasure of backups.
- Symbol/import extraction is heuristic, not a complete language-server call
  graph. The code index still uses exact cosine scanning; fixtures expose
  latency rather than promising arbitrary monorepo performance.
- Ripgrep candidate discovery honors ignore rules; fallback filesystem walking
  has narrower ignore semantics, documented in technical/07.
