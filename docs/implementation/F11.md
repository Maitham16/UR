# F11 — public SDKs and editor packages

Status: native packages, SDK archives and editor packages shipped through
GitHub/npm/Homebrew; see [F14](F14.md). Marketplace/PyPI publication remains
an external prerequisite. SDK wire revision 1 is independent of the app version.

## Public interface and execution

- `ur-agent/sdk` exports dependency-free Node JavaScript and TypeScript
  declarations: `UrClient`, `query`, `queryJSON`, `stream`, `UrRemoteClient` and
  typed local/remote event, result and approval contracts. A local npm install
  resolves the sibling `bin/ur.js` launcher with the current Node executable;
  no global `ur`, npm-script PATH or separate Bun installation is needed.
  Explicit `bin`/`UR_EXECUTABLE` overrides remain authoritative. Source-only
  development falls back to PATH.
- `sdk-python/` is a buildable Python 3.10+ package with no runtime dependencies,
  also bundled at `sdk/python` in npm. It exposes local and authenticated remote
  clients, streaming, approvals, cancellation and resume using the standard
  library. Wheel and sdist are release artifacts; a PyPI account is not assumed.
- Both local clients use the existing bidirectional native stream-json protocol:
  initialize and user frames over stdin, permission responses over that same
  channel, then EOF after the final result. Prompt text never enters a shell or
  argv. This fixes the real failure where a string prompt created finite input
  and ignored later permission responses.
- A successful local result requires a successful final frame and clean process
  exit after output drains. Split UTF-8 is preserved; malformed frames, bounds,
  absent final results, failed results, timeout and cancellation stay explicit.
  Local `query` declines unhandled approval requests, while `stream` permits
  caller-driven approval UI. Early iterator return cancels local execution;
  SIGKILL follows an uncooperative process after two seconds. Resume uses the
  persisted CLI session identifier. No model strategy or permanent grant is
  silently selected by the SDK.
- Remote clients use the existing authenticated POST `/acp` JSON-RPC service,
  not a parallel server. Exact ACP updates/permission requests remain visible.
  Revision, response identity and contiguous event cursors are validated.
  `disconnect` leaves remote work running; `cancel` requests cancellation;
  resume reconnects without resubmitting a prompt. Mutations are not retried
  automatically. Allow_once/deny is supported without input rewriting.
- Native result usage and `cost_status` remain available. Unknown pricing stays
  unknown; a successful turn is not independent proof of task completion.

## Distribution and editor behavior

`scripts/build-sdk.mjs` produces JS/declarations with TypeScript under Node,
clears stale output and copies only distributable Python source. Root packaging
exports `./sdk`, includes SDK files in native npm archives and checks them in
release hygiene. Python metadata participates in version bump/consistency checks.
`ur sdk init` generates examples for these actual packages, preserving one
canonical command. Technical/05/06/07/11 and SDK/package guides were updated.

VS Code now uses the same real bidirectional stream-json exchange, drains
output on close, preserves split UTF-8 and rejects stale approval callbacks.
The official `@vscode/vsce` packager builds an installable VSIX containing the
compiled extension and license. A real editor-host fixture activates that exact
VSIX, verifies registered commands, sends selected Unicode text through the
actual bridge, observes persisted chat, resumes the same CLI session and cancels
a live controlled child. It does not substitute a fake editor API.

The existing JetBrains client remains a synchronous experimental HTTP client.
It now sends an optional bearer token, supports an explicit base URL, validates
JSON-RPC identity and rejects failed/canceled tasks. It does not claim the full
VS Code streaming/approval UI. Gradle builds the installable ZIP and validates
project configuration, package structure and official binary compatibility
against the declared IDEA 2024.3.7.1 target. The same checks remain in CI.

## Automated release integration

`.github/workflows/integrations.yml` is reusable and accepts an optional pinned
`ref`. It builds/tests SDKs, builds and installs the Python wheel, packages VSIX,
tests the exact VSIX in a real VS Code Linux host with Xvfb, and builds/verifies
the JetBrains ZIP with Gradle 9.4/JDK 21. The VS Code download has an immutable
version and checksum. Both `test.yml` and `release.yml` call the workflow.
Artifact name: **`integration-distributions`**.

Its `*.vsix`, `*.zip`, `*.whl` and `*.tar.gz` are attached alongside native
releases. The workflow requires successful checks before upload and retains
editor-host failure evidence. F14 links the successful production and tagged
release runs and the published artifacts.

Marketplace accounts/publisher credentials are required to publish to VS Code
Marketplace or JetBrains Marketplace. They are not present in this environment.
GitHub release assets and installation from disk provide concrete distribution
without those accounts. Python source/wheel distribution is usable without
claiming a registered PyPI project or publishing credential.

Resources: official [VS Code publishing guide](https://code.visualstudio.com/api/working-with-extensions/publishing-extension)
and [JetBrains Gradle verification documentation](https://plugins.jetbrains.com/docs/intellij/tools-intellij-platform-gradle-plugin-extension.html)
were used for package/host/verification behavior. Existing native stream-json
and ACP implementations define the actual supported transport contract.

responses require `updatedInput` and deny responses require `message`, while

omitted allow input from an independent copy of the exact original request and
provide the required denial message. Explicit replacement input remains
authoritative. Callback mutation alone does not rewrite tool input. The child
fixture now enforces these actual native requirements instead of accepting a
bare behavior string. Focused SDK suite after the correction: **13 passed,
0 failed, 68 assertions**; strict-core and lint also passed.
