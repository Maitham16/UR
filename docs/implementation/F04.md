# F04 — functional evaluation and runner integrity

Status: evaluation implementation shipped and release verified; see [F14](F14.md).
Published model measurements retain their recorded candidate fingerprints.
No final-artifact leaderboard score or competitive parity is claimed.

The canonical six suites have one JSON source and 18 deterministic tasks. All
require actual functional checks. Trusted verifier files are materialized after
the candidate exits; suite save/load preserves starting files. Test generation
uses independent mutation checks, migrations use strict TypeScript plus runtime
checks, Docker tasks build/run images, and Python tasks install into fresh venvs.
Missing prerequisites fail. Imported external tasks cannot pass from plausible
prose; a configured executable grader or official external harness is required.

Eval worktrees now live outside reserved `.ur` state paths, preserving ordinary
file-tool semantics. Per-case metrics bind executable/development bundle,
candidate diff and verifier hashes, actual tool results, budgets, explicit
completion and independent false-completion outcome. Missing human intervention,
rollback or billing observations stay unknown. Offline replay is explicitly
labeled. SDK cost_status marks unknown pricing; an explicit USD budget cannot
silently spend through unknown cost, including Ollama Cloud.

External entrypoints invoke real programs without shell interpolation and retain
redacted invocation/stdout/stderr. Missing runners fail unless skip is explicit.
Harbor 0.24.0 adapter installs a pinned native release and runs UR's own loop.
SWE-bench invokes its official predictions evaluator; Aider requires an explicit
UR runner. Process completion is not automatically scored as a benchmark pass.
The original Harbor qualification task uses an unprivileged Linux container and
independent behavioral verifier. No Node.js/Bun installation is needed inside it.

Evidence collected on 2026-10-21:

- Builtin grader qualification: 23/24 passed initially; the remaining Python test
  used system Python 3.9, below its documented 3.11 requirement. The corrected
  environment rerun passed. All 18 broken-baseline/known-repair checks passed,
  including real Docker builds/runs and Python installs; six schema checks pass.
- Focused eval, report, integration and verification tests: 50 pass / 0 fail.
- Cost evidence tests: 2 pass / 0 fail; actual child process confirms local inference
  zero API estimate vs unknown cloud billing and headless unknown propagation.
- Harbor adapter contract tests: 3 pass. Actual native Linux ARM64 task reward 1/1,
  successful agent exit, ~116 seconds. Initial root bypass failure was preserved;
  task user changed to an unprivileged user and the rerun passed.
- Real MiniMax M3.1 Flash via configured Ollama Cloud: initial development run
  repaired all three functions but passed 1/3 overall after reserved-path tool
  denials exhausted turn budgets. After correcting eval worktree placement,
  rerun passed 3/3 independent tasks, 0 explicit false completions. This small
  selected-model result is not cross-model or frontier-agent parity evidence.
  These development runs preceded the cloud-cost correction, so their numeric
  zero cost must not be read as billed/known cost.
- Standard TypeScript checking passed after these changes; final combined
  production and tagged release checks subsequently passed as recorded in F14.
