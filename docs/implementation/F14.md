# F14 — integration and release qualification

Status: implementation pushed; final corrected-revision CI/publication pending.

Candidate version is synchronized across CLI, native/npm, Node/Python SDK,
VS Code, JetBrains and current installation docs. Public commands retain one
canonical entry point. The obsolete A2A card `--v1` switch was removed; protocol
negotiation compatibility remains internal. Release packaging includes the
dependency-free SDK and tested editor/Python artifacts. Production npm has no
runtime dependencies or install scripts and launches the verified native payload.

Local qualification includes the full macOS suite (3,120 passed before the final
CI corrections), 152-file strict typecheck, lint, secret scanning, reviewed
dependency-backport gate, source/package hygiene, real browser checks, native
Mac archive/npm checks, real Node/Python approval tests, actual VSIX host and
JetBrains compatibility. F04/F05 record bounded real-provider observations;
internal deterministic fixtures do not stand in for benchmark scores.

The first GitHub integration run exposed a Linux VS Code sandbox-helper setup
error. The corrected runner preserves Chromium sandboxing with the verified
helper's required root ownership/mode. All four native jobs and the SDK/editor
job passed at `2e481a27`, including both Linux remote-worker deployments.

That revision's full Linux suite found three source ACP initialization errors
from an unavailable build constant, plus one subprocess descriptor failure.
ACP now uses the existing safe build-version accessor. Unattended workspace
commands explicitly ignore stdin, and early subprocess errors return failure
without replay. New regressions exercise source initialization outside the
checkout and early/missing-process failures. Focused checks: 25 passed; standard
and strict typechecks passed. Native Mac/npm packages were rebuilt and retested.

A fresh Linux container run passed those four formerly failing checks and 3,118
tests overall; its remaining Docker HTTP fixture failure exposed an assumption
that the Docker daemon shares the verifier's localhost. The grader now probes
the real server inside the launched container and checks HTTP status and body,
so remote daemons/VMs work too. Broken-baseline and known-repair checks remain
mandatory. Final Linux qualification passed: **3,119 tests, 0 failures, 6 environment/platform
skips**, 14,538 assertions across 374 files in 145.87 seconds. Log:
`/private/tmp/ur-frontier-linux-final.log`. The rebuilt native Mac smoke check,
lint and source archive check also passed. Immutable-tag CI remains required.

The next GitHub run (`39550258969`) passed all native and SDK/editor jobs but
failed a shell lifecycle check with a blank exit 1. Upstream's investigation
of [Bun #34785](https://github.com/oven-sh/bun/issues/34785) identifies a Bun
1.3.14 extra-stdio descriptor ownership bug: collecting an earlier browser
subprocess can close a descriptor reused by an unrelated command. This matches
the intermittent Linux launch failures after browser tests, although the dropped
diagnostic prevents proving that specific failure from its original log.
CI, source development and native compilation now pin stable Bun 1.4.3, which
includes the upstream fix. Runtime notices and the deferred Windows compiler
checksum/revision match the new pin. Earlier F01/F02/F12 and benchmark records
retain their actual 1.3.14 provenance. Shell asynchronous errors also retain the
OS diagnostic, with a real missing-executable regression. Users still receive
the runtime inside the standalone executable; no separate Bun install is added.

Qualification with Bun 1.4.3 passed: macOS **3,124 passed, 2 platform skips,
0 failures**, 14,574 assertions (243.95 seconds); fresh Linux container **3,120
passed, 6 environment/platform skips, 0 failures**, 14,542 assertions (148.52
seconds). Focused compiler/shell/workflow checks passed 43 tests. The rebuilt
native Mac executable passed all 13 checks; the actual npm install passed with
scripts disabled, zero dependencies, Bun absent and a subsequent offline launch.
Standard/strict typechecks, lint, secret scan and release checks passed. Logs:

`/private/tmp/ur-runtime-new-linux-corrected.log`,
`/private/tmp/ur-runtime-new-native-smoke.log`, and
