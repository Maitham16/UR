# F10 — Onboarding, progress and review

Status: locally verified; installed interactive first-use and provider-specific
model success require release/live qualification.

The existing setup screen now includes provider/model selection, API-key picker
guidance, a small read-only first task, cost, interruption, recovery and review
instructions. It adds no setup gate or permission change. Existing progress
UI continues to show actual activity, failures and retries.

`ur doctor --readiness [--json]` and `/ur-doctor [--json]` share
`collectReadiness`/`formatReadiness`. The compatibility `urDoctor` API delegates
there too. The report checks the selected provider rather than requiring
Ollama for API users. It does not generate a model response, spawn MCP servers,
reconcile background tasks or migrate proof records. Plain `ur doctor` retains
installation/update diagnostics. No new public command was introduced.

Review shows bounded changed-file summaries with Git fsmonitor disabled,
spec proof freshness, historical goal outcome freshness, reported cost plus
unknown-cost calls, persisted background state and recovery/cancel commands.
Old proof PASS is unverifiable/PARTIAL without rewriting the record. Verified
goal history remains historical and gets current/stale/unverifiable labels.
Background rows are explicitly saved snapshots, not liveness assertions.
No transcripts, raw tool output or provider secrets are copied to the report.
