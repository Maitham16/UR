# F12 — durable remote control and native deployment

Status: locally verified (2026-10-21); remote release qualification remains F14.

The existing HTTP endpoint supports durable prompt IDs, contiguous persisted
event replay, authenticated pending approvals, cancellation, resume and scoped
expiring device credentials. Revocation persists across server replacement. A
stale cross-process read is rechecked under the claim lock before launching a
prompt. Matching requests reuse the same run; changed content cannot reuse its
ID. Failed or absent native terminal results fail even after partial text.

Ownership records fence live children. Interrupted sessions disclose uncertain
effects and resume the saved CLI conversation for model-led reconciliation.
Torn event journals fail visibly. Permission answers resolve only a current
pending request. This does not guarantee exactly-once arbitrary external effects.

`deployment/acp/Dockerfile` builds from the exact extracted native Linux payload
with a pinned Ubuntu base, unprivileged UID 10001, private state and workspace
volumes, and no external Node/Bun runtime. The recipe documents provider/model
selection, credentials, lifecycle, artifact/log retrieval, preview exposure and
TLS/tunneling. OS security packages are resolved at build time; record the built
image digest for repeatable deployment. Single-user writable state is explicitly
not hostile multi-tenant isolation. Hosted accounts and public URLs are operator
inputs, not implied cloud services.

Local evidence:

- HTTP recovery, runner error and team tests are included in the full passing
  3,120-test suite. Real killed-worker fixtures check unknown-outcome recovery,
  permission cancellation, stale claims and corrupt-journal rejection.
- Built the actual candidate from current source on Linux ARM64 inside Docker
  with frozen dependencies and Bun 1.3.14. Its resources were built fresh.
- `node scripts/acp-container-smoke.mjs --native-dir dist-native/linux-arm64`
  passed all nine checks: nonroot, read-only application, no external runtime,
  authentication, actual native Write approval, idempotency, scoped device
  revocation, replacement-container replay and native session resume.
  Three controlled provider completions drove the actual native process/tools.
  Log: `/private/tmp/ur-frontier-container-smoke-final.log`.
- Initial deployment qualification exposed a missing explicit `UR_MODEL` for
  fresh noninteractive workspaces. The corrected recipe sets the selected model
  as a runtime input and preserves existing workspace-selection semantics.

The same smoke script runs in both Linux native CI jobs against fresh payloads.
It does not measure model quality. It removes its containers, volumes, image and
ephemeral token; failures retain private diagnostic logs.

Updated technical/08, /09, /11, /14, docs/ACP and deployment instructions describe
the supported contract and limitations. Docker semantics follow the official
[Dockerfile](https://docs.docker.com/reference/dockerfile/) and
[runtime](https://docs.docker.com/engine/containers/run/) documentation.
